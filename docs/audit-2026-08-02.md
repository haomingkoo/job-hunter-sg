# Over-engineering audit, closed 2026-08-03

This file records the current disposition of the 2026-08-02 whole-repository audit.
The original 25-row ledger and its line estimates remain in git history. It is not
retained here because its paths, counts, and proposed deletions became stale as the
work landed.

## Removed or consolidated

- Unreachable candidate-profile evaluation and interview-preparation prototypes,
  including their self-testing suites and impossible frontend renderer.
- The unbound ATS analysis tool, unused MCP payload helper, unused model/tracing
  helpers, unread SSE setting, and other dead imports and aliases.
- The hidden agent-tool registry and defaults. Every agent now receives its tools and
  subagents explicitly.
- Three duplicate power-skill loops, duplicate analytics cache fields, repeated
  recruitment service errors, duplicate job-term display formatting, repeated
  authenticated frontend request/download code, and the second skill flattener.
- Redundant Pydantic validators and serialization recursion, write-only frontend state,
  incomplete hard-coded template order, and a duplicate story-tag endpoint/list.
- Unused `TailoredResume.match_before` and `match_after` ORM attributes. Their nullable
  physical columns remain for additive-database compatibility.
- Three assessment settings that were emitted as policy controls but never controlled
  the open-agent runtime: specialist validation attempts, specialist concurrency, and
  judge validation attempts.

## Findings corrected rather than deleted

- Read endpoints no longer construct live models, resolving the no-key `GET /threads`
  failure.
- Target-assessment correction is live, so its correction field, configured attempt
  count, prompt receipt, and frontend status are current behavior rather than residue.
- API and backfill job-term labels share one implementation and acronym vocabulary.
- Contact-heading parsing uses the shared classification map.
- The local SQLite path is module-relative, so API and MCP launches share one database.

## Deliberately not unified

The old ledger proposed one universal bullet-marker regex and replacing the scorer's
section normalization map with the broader shared heading map. Those are not safe
deduplications: the call sites implement different parsing grammars, and broadening the
heading map changes inline-heading splitting and the meaning of `additional information`.
They remain separate domain rules until one canonical grammar and migration are designed
and regression-tested. Similar-looking literals are not treated as duplicates when their
semantics differ.

## Result

The confirmed safe residue was removed through PRs #167 and #169-#176. Tests that only
proved deleted code could test itself were removed with that code. Current behavior is
covered at reachable API, service, prompt-payload, and frontend seams. No known safe
deletion from the audited ledger remains outstanding.
