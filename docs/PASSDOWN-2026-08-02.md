## Fixed today, with the evidence

1. **`GET /threads` was a 500 without a SEA-LION key.** Six read-only endpoints took four
   `Depends` that each built a `ChatOpenAI`. `_read_team(db, telemetry)` now passes `None`
   for every model collaborator. In a browser this looked like a CORS error, because the
   exception escapes before `CORSMiddleware` adds headers. That cost an hour; do not be
   fooled by it again.
2. **One unquotable preference discarded a whole turn**, including eight gate-passing resume
   edits. `evidenced_preference_updates` now drops the bad update and keeps the turn.
   Reverses revision 3 of `docs/v4-146-coordinator-loop.md`, recorded there as revision 5.
3. **The agent could not learn resume block IDs.** `propose_resume_edit` needs opaque hashes
   (`b_87156122e7ce1066fa93`) and nothing readable contained one, so it guessed, got
   "Unknown resume block.", and looped to the iteration cap. The turn payload now carries
   the resume as `block_id: text` per line and the refusal names every valid ID.
4. **The orchestrator prompt gated edits on a tool that path never binds.** It said only
   propose edits when "the `propose_edit` tool is available"; the V3 runner binds
   `propose_resume_edit`. Unsatisfiable, so zero edits ever. This is the PRD's V8
   before-state, "proposed edits have never been observed reaching the table on a live run",
   and `runner.py:206` already recorded the symptom.
5. **The score gate rejected its own instruction.** The prompt asks `score_reason` to explain
   `evidence_support_score`; the gate then required every number in it to appear in the
   resume. Only that one value is exempt now.

## Not fixed. Start here.

### 1. Resumes are chopped mid-sentence (biggest correctness issue)

`create_resume_document` treats each source line as a block and never rejoins a wrapped
sentence. On `tmp/pdfs/haoming-ai-ml-manager/resume.txt`: 72 blocks, **17 are one sentence
split in two**. Both PDF and txt, so it is not the parser.

    block N   : "...agentic AI delivery. Led the Conversion Accelerator Program"
    block N+1 : "at Micron, a four-fab AI-enabled transformation aligning 3,0..."

This is why gates reject rewrites with "Missing facts from original: 6, 9" (the numbers are
in the other half) and "Rewrite is 44 words (max 40)" (completing the fragment).

**Do not fix casually.** Block IDs are content hashes, so rejoining changes every ID and
invalidates stored `candidate_profile_artifacts` checkpoints, pending `proposed_resume_edits`
rows, and artifact citations. Needs a migration.

**Check first:** the v1 editor renders complete bullets from the same PDF. If
`resume_structurer.py` already gets this right, the fix is to reuse it rather than write new
joining logic.

### 2. The judge's `revise` silently discards everything

`prompts/target_assessment.py` tells the judge `revise` means a repairable overstatement. In
code, `revise` and `block` both yield `quality_blocked`, wipe `specialist_runs` and
`synthesis`, and raise before the edit-persistence loop, so every drafted edit is discarded.
`max_attempts=1`, `correction=None`, no re-judge exists. Smallest fix: drop `"revise"` from
the `Literal` at `assessment_contracts.py:171`.

### 3. Stored artifacts claim prompts that never ran

`target_assessment_execution_policy()` stamps `specialist_prompt_version` and
`synthesis_prompt_version` onto every artifact. Both prompts were deleted today because
nothing sent them. Removing the keys changes a persisted policy shape, so it needs a
decision and probably a migration.

### 4. Replies render as one wall of text

The prompt asks for blank lines between paragraphs. The model ignores it, consistently.
Prompt text is not a bound. Paragraph it in code before rendering.

## Traps that cost time today

- **A green suite proves very little on the agent paths.** All 922 passed through four
  consecutive live failures. `scripted_deep_agent.py` returns a submission by construction,
  so it can never reproduce a model that will not stop, or one that answers in prose.
- **A refusal a model cannot act on is a refusal it will retry until the cap.** Three
  instances so far: `read_candidate_evidence` (12 calls), `write_todos` (11), and
  `propose_resume_edit` (15). When a tool refuses, name the alternative or hand over the
  missing values. The repeat guard does not save you; it refuses identically forever.
- **Local signup fails closed** with no SMTP. Insert a user with `bcrypt.hashpw` directly;
  `resume_versions` needs `source`, `job_title`, `job_company`, `score`, `word_count`,
  `updated_at` all non-null.
- **Building the frontend into `backend/static/`** mounts the SPA catch-all and turns
  method-not-allowed into 404. Gitignored now.

## Owner's intent, in their words

The AI writes the resume. It uses only evidence from the candidate's resume and the job
description. It never makes things up or overstates, and it still gives the candidate a real
chance at an interview without lying. It should feel autonomous like a coding agent: the
candidate can ask anything about their job hunt, interrupt, change direction, ask why,
compare roles, or say "just finish it", and it keeps building toward a resume worth sending.
Flexible inside job hunting, not a general chatbot.
